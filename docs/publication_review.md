# 公开范围与待审核材料

当前目录是 GitHub 发布候选，Phase 5对限定的自有源码、原创文档与数值摘要给出READY；全部材料的公开授权与隐私审核尚未完成。详见 [Phase 5报告](phase5_report.md)。本说明记录待确认事项，不把“来源不明/授权待确认”解释为已证实侵权。没有添加 LICENSE，没有批准整包公开，也没有执行上传。

来源可追溯、运行可验证和有权再分发是三个独立条件。Phase 5 中用户已明确确认源码全部由本人编写，见 [作者确认记录](phase5_authorization.json)；源码共同作者授权不再是阻塞项。此确认不自动授予竞赛资料、DEM、模板、论文或原图片的再分发权。

## 1. 已有审核范围

[review_required.csv](review_required.csv) 保留 Phase 2 的194条材料审核记录：124条未复制，70条仅在本地冻结/隔离保存。它是按文件登记的历史清单，不是194项已确认侵权或隐私泄露。

新增 [figures.csv](figures.csv) 对15张代表图片补充论文图号、来源哈希、生成脚本、对应数据和限制；它与历史材料清单有重叠，不能直接相加作为独立文件总数。15张图片均为 `authorization_status=pending_review`、`publication_status=not_copied`，没有进入公开候选文件或 README 图片链接。

## 2. 隐私与元数据

Phase 2 已记录部分冻结工作簿含作者信息或本机路径；为保留正式证据，没有改写这些文件。Phase 4 只读核对的最终论文也存在作者/最后修改者等 Office 元数据，没有在公开说明中复述私人值。

原附件28张 PNG 的文本元数据扫描未检出 Windows 绝对路径、邮箱或手机号模式，26张含 Software 字段。此结果仅限元数据文本，不涵盖所有图像像素、PDF属性或嵌入对象；不能据此把全部图片标为隐私审核通过。图片审查的证据层次和图号差异见 [figures.md](figures.md)。

公开文档使用项目相对路径或明确占位路径，不应引入原机器的用户目录、联系方式、许可证标识或凭据。`run_manifest.json`、测试日志及本地审计快照可能记录实际输入绝对路径，因此继续留在忽略区。Gurobi 许可证文件、WLS密钥和令牌不属于可发布材料。

## 3. 隔离规则与实际含义

[.gitignore](../.gitignore) 继续隔离 `results/reference/`、`experiments/**/results/`、`review_hold/`、`.release-audit/`、原始/处理中数据内容、运行产物、本地环境与缓存，仅保留必要的数据说明文件。

忽略规则用于减少误提交，不是授权证明，也不能阻止强制加入文件、人工压缩上传或已经跟踪的文件继续被提交。发布前应逐项检查实际 Git 索引和待发布树，不能仅检查 `.gitignore` 文本。当前规则也意味着公开克隆不会自动拥有本地待审结果和原始数据；README 的归档复核命令以具备获准本地材料为前提。

[publication_gate.json](publication_gate.json) 是 Phase 2 的历史门槛记录，仍保留 `public_upload_allowed=false` 和 `license_assigned=false`。其中“完成Phase3路径和输出隔离”已由后续报告验证完成，但不代表其他公开条件自动完成；本阶段未通过覆盖历史记录来宣称获准公开。

## 4. 后续公开处理

1. 按材料和贡献者登记明确结论：允许公开、限定范围/署名条件，或仅供本地使用；保存依据，不能只依赖文件已存在于候选目录。
2. 对允许公开但需要脱敏的结果或图片创建单独展示副本，记录来源、改动和新哈希；保留正式冻结原件及历史溯源，不解除全部忽略规则。
3. 对未获数据再分发许可的材料保留外部输入方式，明确文件结构和缺失提示，不补造数据或缓存。图像来源/授权无法确认时继续使用文字说明。
4. 代码作者已确认，后续由作者选择适用 LICENSE；没有 LICENSE 不等于源码不能展示，但不应宣称已授予通用开源复用许可。第三方材料不能随源码统一授权。
5. 最终发布前审核实际待跟踪文件、Markdown链接、图片与Office元数据、凭据和本地路径，确认 README 对材料可获得性及验证程度的说明与发布内容一致。

这些是后续公开准备事项，本阶段保留所有待审材料，没有擅自删除、公开或修改冻结结果。
