## 2. 主要工程差异

| 整理前 | 整理后 |
|---|---|
| 从脚本父目录推算旧中文兄弟目录，部分读取依赖 CWD | 从项目根定位；外部数据仅通过显式 raw/input/template 参数提供 |
| 算法模块、实验和绘图分别写固定 results 目录 | 默认写入 `results/runs/<独立标识>/problemN/` |
| 基线与输出复用同一常量 | Q1/Q2 基线、Q3 精英池/缓存、Q4 旧论文表明确拆开 |
| 缺失已填写 Q3 模板 | 明确读取综合提交表 `Q3_通信保障`，没有伪造同名原件 |
| 几个辅助模块在导入时读取/绘图/建目录 | IO 移入 main 或实际保存函数；导入不启动实验 |
| 缓存直接 pickle.load | 字节哈希及输入指纹验证后加载，保持原类模块身份 |
| 新产物缺少统一来源记录 | 统一入口记录命令、版本、源码/输入/输出哈希及失败状态 |

41 份现有 Python 文件均已审查；检索未发现残留的原项目绝对路径、`.python_packages` 或 CWD 下固定 `results` 路径。原始 Excel 文件名、工作表名和 DEM 文件名保留，以维持数据接口。

导入采用集中 bootstrap 保留历史模块名，避免改写函数接口和 pickle 类身份；没有引入复杂包架构。Q3 缓存脚本直接执行时转发规范模块入口，避免将新 pickle 类写成 `__main__`。

`run.py` 拒绝复用已存在的运行目录。输入目录与 reference 受只读保护；参数化输出 helper 拒绝当前 run 以外路径。旧 Q4 工作簿的追加操作先在 runs 创建可写副本。冻结结果仍保持原有只读属性。
